## How it works
- The role scored: another program starts the harness as a child, passes a prompt, tool
  allowlist and system-prompt addition, parses its structured output, scopes its secrets
  and kills it on timeout. Not human-at-a-keyboard UX, not model quality.
- **Tier-1** (static source audit): 8 weighted categories, 42 criteria scored 0-3 with
  citations, weighted total /81. One pass, about +/-3 noise.
- **Tier-2** (live): T1-T7 driver-contract tests scored 0-3 (/21) plus a golden task
  (add `--version` to a CLI) for task success, tokens, USD and wall time. Same model
  (`qwen/qwen3.7-flash` via OpenRouter) for 7 of 9 harnesses; fx (grok-4.6) and nanocodex
  (mimo-v2.6-pro) are not comparable on cost or time.
- One manifest per run under `runs/`; README block, RESULTS.md and runs/INDEX.md are
  generated by `bench-kit render`. Benchmark card, noise band, leak register and
  changelog: [METHOD.md](METHOD.md).

## Run it

```bash
# validate the published evidence (stdlib only; this is the "Validate benchmark" CI job)
python scripts/validate_benchmark.py
python -m unittest discover -s tests -v

# rebuild the standard files from the scores + raw evidence, then stats, render and lint
python scripts/backfill_standard.py            # --check only compares
uv tool install git+https://github.com/aaronjmars/bench-kit@v0.2.0
bench-kit stats && bench-kit render && bench-kit lint

# re-render the table images in images/
uv run --with matplotlib python make_images.py
```

To reproduce a live run: install the harness (or use `npx`/curl per its docs), export
`OPENROUTER_API_KEY` from your own secret store (never commit it), and follow the exact
invocation and runner scripts in `t2/<harness>/RESULT.md`. The validator checks that every
harness has a complete T1-T8 report and task verdict, parses each non-empty JSON/JSONL
capture, and rejects credential-shaped files under `t2/`. Empty captures stay valid because
some startup and cancellation failures intentionally produce no structured output.

## Layout

| Path | What |
|---|---|
| `runs/<id>/` | `manifest.json` + `samples.jsonl` per run (bench standard); `runs/INDEX.md` lists them |
| `RESULTS.md` | every run, newest first (generated, do not edit) |
| `METHOD.md` | benchmark card: tasks, metrics, judge, noise band, leak register, changelog |
| `NEXT.md` | open work and harnesses to track |
| `BENCHMARK.md` | full study: contract, Tier-1 scorecard and reasoning, Tier-2 results |
| `docs/` | long write-ups (`2026-10-04-harness-comparison.md`: all comparison tables and rankings) |
| `t2/<harness>/` | `RESULT.md` (that harness's Tier-2 write-up), raw evidence (`*.jsonl`, `*.json`, `*.out`, `*.err`, `*.log`), runner scripts, config overlays; flue/eve include their authored agent projects |
| `scripts/validate_benchmark.py` | evidence validator (CI) |
| `scripts/backfill_standard.py` | writes `runs/*` from the per-test scores and the raw golden-task evidence |
| `tests/` | unittest suite for both scripts |
| `make_images.py`, `images/` | renders the comparison tables as PNGs |

Not tracked (see `.gitignore`): the harness source clones (re-clone from upstream) and
every per-run auth / home / state dir (they hold credentials).

## Harnesses

omp (Oh My Pi, can1357/oh-my-pi), pi (earendil-works/pi), fx (vercel-labs/fx), opencode
(sst/opencode), dsh (DeepSeek Harness, deepseek-ai/deepseek-harness), crush
(charmbracelet/crush), nanocodex (gakonst/nanocodex), and two frameworks, flue
(withastro/flue) and eve (vercel/eve). The frameworks are not drop-in CLIs: a control plane
must author and scaffold a TypeScript agent project before driving `flue run` /
`eve invoke`; they are scored on the same axis with the scaffold held constant.
